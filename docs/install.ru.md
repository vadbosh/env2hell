# Установка подробно

## Что установщик затрагивает

Ничего за пределами домашнего каталога. А именно:

| Путь | Что происходит |
|---|---|
| `~/.local/bin/secrets-guard` | копируется сама проверка |
| `~/.local/bin/safe-env` | копируется команда со скрытием значений |
| `~/.claude/settings.json` | добавляется одна запись `PreToolUse` |
| `~/.codex/hooks.json` | добавляется одна запись `PreToolUse` |
| `~/.config/opencode/opencode.json` | регистрируется плагин, записываются правила разрешений |
| `~/.config/opencode/plugins/secrets-guard.ts` | копируется плагин |
| `~/.claude/rules/`, `~/.config/opencode/instructions/`, `~/.codex/memories/` | файл правила |

Записи вносятся только в те ассистенты, которые уже установлены. Создавать
дерево настроек для ассистента, которым вы не пользуетесь, значит просто
засорять домашний каталог.

Файл, который предстоит изменить, сначала копируется в
`<файл>.bak.<отметка времени>`. Повторный запуск установщика ничего не
перезаписывает: совпадающее содержимое пропускается, поэтому одинаковые копии
не накапливаются.

## Как выбрать состав установки

```bash
./install.sh --dry-run          # показать план, ничего не менять
./install.sh --ide opencode     # только один ассистент
./install.sh --bin-dir ~/bin    # положить обе команды в другое место
./install.sh --no-rule          # поставить проверку, файл правила пропустить
```

На машине с настройками, которые жалко потерять, стоит начать с `--dry-run`.
Он печатает те же строки, что и настоящий запуск, но с пометкой `would`.

## По каждому ассистенту

### Claude Code

Запись, которая добавляется в `settings.json`:

```json
{
  "matcher": "Bash",
  "hooks": [{
    "type": "command",
    "command": "/home/you/.local/bin/secrets-guard",
    "timeout": 5,
    "statusMessage": "secrets-guard..."
  }]
}
```

Хук, завершившийся с кодом 2, отменяет вызов и передаёт модели то, что написал
в поток ошибок. Любой другой код завершения пропускает команду.

Порядок записей важен только в том смысле, что выполняются все хуки с шаблоном
`Bash`; если у вас уже стоит проверка на разрушающие команды, эти две не мешают
друг другу.

### Codex

Устройство то же, файл — `~/.codex/hooks.json`, шаблон записан как регулярное
выражение (`^Bash$`). Раздел `[hooks.state]` в `config.toml` править руками не
нужно: его ведёт сам Codex.

### Opencode

Здесь два слоя, и нужны оба:

1. **`permission.bash`** — правила прямо в `opencode.json`. Дёшевы и действуют
   до загрузки чего бы то ни было. Сравнивают начало строки, поэтому ловят
   `env`, но не `env | grep KEY`.
2. **`plugins/secrets-guard.ts`** — плагин на событии `tool.execute.before`,
   вызывающий тот же `secrets-guard`. Именно он ловит конвейеры, обёртки и
   составные команды.

Установщик **перезаписывает** правило `"env": "allow"`, если оно там было.
Явное разрешение для команды, печатающей всё окружение, — ровно та дыра, ради
которой всё это сделано, а в списках разрешений, собранных вручную, она
встречается часто.

Если `secrets-guard` не найден в `PATH`, плагин печатает предупреждение и
отключается, вместо того чтобы блокировать всё подряд. Проверить можно так:
`which secrets-guard`.

## Windows

Установщику на PowerShell не нужны ни Python, ни Git Bash. Он записывает те же
настройки с одним отличием: хук регистрируется с `"shell": "powershell"` и
указывает на `secrets-guard.ps1`.

```powershell
.\install.ps1
.\install.ps1 -DryRun
.\install.ps1 -Ide codex
.\install.ps1 -BinDir "C:\tools\env2hell"
```

По умолчанию команды кладутся в `%LOCALAPPDATA%\Programs\env2hell`.

### Если файл не запускается

Политика выполнения PowerShell по умолчанию не пускает неподписанные скрипты.
Запустите установщик с явным обходом — он действует только на этот запуск и
ничего не меняет в настройках машины:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Если удобнее разрешить локальные скрипты вообще, это настройка уровня
пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### Если есть Git Bash или WSL

Тогда работает и версия для POSIX, и выбрать лучше её: одна проверка, одно
поведение, один набор результатов тестов. Ставится из той же оболочки командой
`./install.sh`.

## Перезапустите ассистента

Хуки, плагины и правила разрешений читаются один раз — при запуске ассистента.
До перезапуска `secrets-guard` установлен, но ещё ничего не проверяет. Это
самая частая причина жалобы «поставил, а оно не работает».

## Проверка установки

Установщик заканчивается собственной проверкой: передаёт `secrets-guard`
команды `env` и `echo hi` и ждёт кодов 2 и 0. Дальше можно проверить
подробнее:

```bash
./tests/test_guard.sh                       # 47 случаев, версия для POSIX
./tests/test_guard.sh --pwsh                # те же 47, версия для PowerShell
./tests/test_guard.sh --guard ~/.local/bin/secrets-guard   # установленная копия
```

Чтобы увидеть работу внутри ассистента, попросите его выполнить `env`. В ответ
должно прийти сообщение об отказе, а не список переменных.

## Разбор отказов

**Ничего не блокируется.** Ассистента не перезапустили. Если перезапустили —
проверьте, что запись действительно на месте:

```bash
jq '.hooks.PreToolUse' ~/.claude/settings.json
jq '.plugin, .permission.bash.env' ~/.config/opencode/opencode.json
```

**Блокируется всё, включая обычные команды.** Запустите набор тестов. Если он
проходит, `secrets-guard` работает как задумано и команда действительно совпала с
шаблоном — в сообщении об отказе указано, какой проход сработал. Если случай
всё же разобран неверно, он сначала добавляется в `tests/test_guard.sh` как
падающий, и только потом чинится.

**Установщик пишет, что файл настроек — не JSON.** В этом случае он ничего не
записывает и не трогает. Исправьте файл (обычно виновата лишняя запятая) и
запустите ещё раз.

**`secrets-guard` не найден в `PATH`.** Добавьте каталог в `PATH` или поставьте
заново с `--bin-dir`, указав каталог, который там уже есть. Хуки ассистентов
пользуются полным путём и работают в любом случае; `PATH` нужен плагину
opencode и ручному запуску.

## Удаление

```bash
./uninstall.sh --dry-run
./uninstall.sh
```

Убираются записи хуков, плагин, правила разрешений и файл правила. Сохранённые
копии намеренно остаются: это единственный след того, что было в настройках
раньше.
