# Что считается секретом

`safe-env` решает по каждой переменной, похоже ли значение на учётные данные.
Совпадение заменяется на `<REDACTED:длина>`, остальное печатается как есть —
поэтому вывод остаётся пригодным для работы:

```
ANTHROPIC_MODEL=glm-5.2
PATH=/usr/local/bin:/usr/bin:/bin
TAVILY_API_KEY=<REDACTED:57>
```

Длина сохраняется намеренно. Она позволяет различить два разных ключа в одном
выводе и не даёт ничего, что помогло бы нападающему.

## Распознаваемые форматы

| Поставщик | Шаблон |
|---|---|
| Ключ доступа AWS | `AKIA` и 16 знаков в верхнем регистре |
| GitHub, обычный | `ghp_` / `gho_` / `ghs_` / `ghu_` / `ghr_` и 36 знаков или больше |
| GitHub, детальный | `github_pat_` и 22 знака или больше |
| GitLab | `glpat-` и 20 знаков или больше |
| Slack | `xox` плюс `b`/`a`/`p`/`r`/`s`, дефис и 10 знаков или больше |
| Tavily | `tvly-` и 10 знаков или больше |
| Google | `AIza` и 35 знаков |
| Stripe, боевой | `sk_live_` / `rk_live_` и 20 знаков или больше |
| Семейство OpenAI | `sk-`, возможно `sk-or-v1-`, `sk-proj-`, `sk-ant-`, и 20 знаков или больше |
| Atlassian | `at-` и 30 знаков или больше |
| JWT | `eyJ…` `.` `eyJ…` `.` |
| Закрытый ключ | строка `BEGIN … PRIVATE KEY` |
| Пароль внутри URL | `://пользователь:пароль@` |
| Пароль в SQL | `IDENTIFIED BY '…'` |

## Общие запасные шаблоны

Именованные форматы закрывают поставщиков, о которых вы знаете. Тех, о ком не
знаете, ловит форма значения:

| Форма | Что ловит |
|---|---|
| 32 шестнадцатеричных знака и больше | ключи без приставки, похожие на хеш |
| 20+ знаков, точка, ещё 8+ | токены вида `key.signature` |
| 40 непрозрачных знаков и больше | длинные случайные строки |
| участок из 40+ знаков, содержащий точку | составные токены |

Третья строка появилась из-за настоящего промаха. Токен вида

```
<32 шестнадцатеричных знака>.<16 знаков>
```

ранняя версия напечатала полностью: точка разрывала любой участок, достаточно
длинный для остальных правил, и не сработало ни одно. Строку `key.signature`
добавили именно под эту форму — и это довод за то, чтобы незнакомый формат
токена проверять, а не считать покрытым.

## Как проверить формат

Живой ключ для проверки подставлять нельзя. Соберите значение той же формы:

```bash
env -i PATH="$PATH" \
    SAMPLE='glpat-EXAMPLEEXAMPLEEXAMPLE1234' \
    safe-env | grep SAMPLE
```

Скрытое значение в выводе означает, что шаблон работает:

```
SAMPLE=<REDACTED:31>
```

Та же проверка в PowerShell:

```powershell
$env:SAMPLE = 'glpat-EXAMPLEEXAMPLEEXAMPLE1234'
.\bin\safe-env.ps1 | Select-String SAMPLE
```

## Как добавить формат

Файла два, и они должны меняться вместе:

- `bin/safe-env` — строка `RE` в блоке `BEGIN` программы `awk`
- `bin/safe-env.ps1` — массив `$patterns`

Добавьте одно и то же выражение в оба, затем проверьте собранным значением, как
выше. Формат, добавленный в один файл и забытый в другом, хуже, чем не
добавленный никуда: получается машина, где поведение зависит от операционной
системы, а этого никто не ожидает.

## Чем от этого отличается запрет команд

`safe-env` скрывает значения. `secrets-guard` запрещает команды, и список у
него свой — он лежит в `lib/patch_config.py` (`DUMP_RULES`, `READERS`,
`SECRET_FILES`), чтобы установщик и документация не разошлись.

Файлы, которые считаются хранилищем секретов:

```
*.env  *.pem  *.key  *.p12  *.pfx  *id_rsa*  *id_ed25519*  *id_ecdsa*
.aws/credentials  .docker/config.json  .kube/config  .azure/
.git-credentials  .npmrc  .pypirc  .pgpass  .my.cnf
~/.bashrc  ~/.zshrc  ~/.profile  ~/.bash_profile  ~/.zshenv  ~/.netrc
_netrc  Microsoft.PowerShell_profile.ps1          ← написания для Windows
/proc/*/environ  *credentials*  *secrets*
```

Разделитель пути принимается любой, поэтому то же хранилище в написании для
Windows — `C:\Users\you\.aws\credentials` — ловится так же, как путь через
прямой слэш.

Чтение любого из них через `cat`, `head`, `tail`, `less`, `strings`, а также
через `type` и `gc` из PowerShell, запрещено. Перечислить их, переместить или
проверить существование можно: запрет касается печати содержимого, а не самих
файлов.

## Если ключ всё же утёк

Выпустите новый. Не стоит рассуждать о том, кто мог его увидеть: журнал сессии
лежит на диске и, возможно, уже попал в ночную сводку.

Поиск по приставке ключа в хранилищах памяти покажет, насколько далеко он
разошёлся, и это полезно знать. На решение это не влияет — ключ меняют
независимо от того, что нашёл поиск.
