# Как это устроено

## В чём сложность задачи

Хук видит ровно одно: строку команды до запуска. Ему нужно ответить на один
вопрос — напечатает ли эта команда учётные данные — и ответить без разбора
синтаксиса оболочки. И ответить быстро: он запускается перед каждой командой,
и его время прибавляется к времени каждой из них.

Два очевидных подхода не годятся:

**Слишком узко — сравнивать начало строки.** Проверка видит тогда только первое
слово. `env` она поймает, а `rtk env` — уже нет: строка начинается с `rtk`.
И `ls && env` не поймает: там `env` стоит вторым.

**Слишком широко — искать слово в любом месте строки.** Оба этих случая
поймаются. Но под запрет попадёт и обычная работа, потому что слово `env`
встречается в командах постоянно:

```bash
source env/bin/activate          # виртуальное окружение Python в каталоге env
python -m venv env               # его создание
git commit -m "fix env parsing"  # слово в сообщении коммита
grep -rn "env" src/              # поиск по коду
```

Ни в одной из них `env` не является командой: это имя каталога, слово в тексте,
строка поиска. Разработчик, которому запретили активировать виртуальное
окружение, выключит такую проверку в тот же день.

Поэтому проверка идёт в два прохода, и каждый смотрит на свою версию строки.

## Проход A — команды, печатающие окружение

Сначала из текста убирается всё, что стоит в кавычках:

```
jq -r '.a | select(.k|test("^(env|set)"))' f.json
    ↓ содержимое одинарных и двойных кавычек заменяется на Q
jq -r Q f.json
```

И только потом строка делится по разделителям оболочки (`|`, `||`, `&&`, `;`,
`&`), а у каждого куска смотрится первое слово. Слово внутри программы в
кавычках к этому моменту уже удалено, поэтому принять его за команду нельзя.

Это разделение появилось не из общих соображений. До него `secrets-guard`
заблокировал ту самую команду, которая правила его собственные настройки:
в фильтре `jq`
стояло `test("^(env|printenv|set)")`, а при делении по `|` из этого получаются
голые слова `printenv` и `set`.

Обёртки пропускаются до чтения имени, поэтому распознаются и `sudo env`, и
`rtk env`, и `time env`:

```
sudo rtk env    →  пропустить sudo, пропустить rtk, смотреть env
```

Кусок, который вообще не похож на имя команды — начинается с `"`, `=`, `{`,
`[`, `$` или `*`, — пропускается, а не разбирается наугад.

### Где проходит граница

| Запрещено | Разрешено | Почему |
|---|---|---|
| `env` | `env VAR=1 cmd` | Вторая форма задаёт переменную одной команде и ничего не печатает. |
| `printenv` | `printenv PATH` | Обращение к одной переменной по имени — как раз то поведение, которое нужно поощрять. |
| `export -p` | `export PATH=/x` | `-p` перечисляет всё, присваивание не перечисляет ничего. |
| `set` | `set -e` | `set` без аргументов печатает все переменные оболочки. |
| `declare` | `declare X=1` | То же самое. |
| `history` | `helm history`, `docker history` | Благодаря пропуску обёрток решение принимает первое слово. |

## Проход B — файлы, где лежат учётные данные

Проход B требует совпадения сразу по двум признакам: есть читающая команда
(`cat`, `head`, `tail`, `less`, `strings`, а также `type` и `gc` из PowerShell)
и есть путь, похожий на хранилище секретов.

Список путей общий для всех систем — разделитель принимается и прямой, и
обратный, потому что в Git Bash или WSL приходит то одно написание, то другое:

| Что | Где |
|---|---|
| `.env`, `*.pem`, `*.p12`, `*.pfx` | везде |
| `id_rsa`, `id_ed25519`, `id_ecdsa` | везде |
| `.aws/credentials`, `.kube/config`, `.docker/config.json`, `.azure/` | везде, на Windows — через обратный слэш |
| `.git-credentials`, `.npmrc`, `.pypirc`, `.pgpass`, `.my.cnf` | везде |
| `.bashrc`, `.zshrc`, `.profile`, `.netrc` | POSIX |
| `_netrc` | Windows: там `.netrc` называется так |
| `Microsoft.PowerShell_profile.ps1` | Windows: в него пишут `$env:API_KEY = "..."` |
| `/proc/N/environ` | только Linux, в других системах такого файла нет |

Две последние строки нужны ровно потому, что список без них был бы половинным:
на Windows роль `.bashrc` играет профиль PowerShell, и ключ в нём лежит так же
открыто.

Ищутся они в разных версиях строки, и в этом всё дело:

- **команда — в тексте без кавычек**: она должна быть настоящей командой;
- **путь — в исходном тексте**: он часто стоит в кавычках, и проход A его бы
  удалил.

Требование обоих признаков сразу удерживает число ложных отказов низким:
в `cat README.md` нет пути к секретам, а `ls ~/.aws/credentials` ничего не
читает.

Поиск команды в тексте без кавычек — это то, что не даёт обычной прозе влиять
на решение. Вот сообщение коммита:

```bash
git commit -m "docs: cat .env ends the same way"
```

Здесь есть и читающая команда, и путь к секретам, и прежняя версия такой коммит
запрещала. Но это слова в аргументе, а не команда: после удаления кавычек они
исчезают раньше, чем команда будет найдена.

Шаблону `.env` нужна граница слева, иначе он срабатывает на обычном тексте.
Настоящий случай из работы над этим репозиторием:

```bash
jq -r '.permission.bash.env' opencode.json | head
```

В `bash.env` есть подстрока `.env`, а `head` — читающая команда, поэтому шаблон
без границы запретил совершенно безопасную команду. Теперь перед `.env` должен
стоять пробел, кавычка, косая черта или знак `=`.

## Отказ в сторону разрешения

Если на вход пришёл не JSON, или в системе нет `jq`, или поле команды пустое —
проверка завершается с кодом 0 и команда выполняется. Инструмент, который ломает
работу ассистента при любой неожиданности, рано или поздно удаляют, а удалённый
не защищает уже ни от чего.

Узкий путь — это как раз запрет: код 2 и сообщение в поток ошибок, которое
ассистент показывает модели. Во всех остальных случаях работа продолжается.

## Задним числом — secrets-redact

Всё, что описано выше, происходит до запуска команды и закрывает целый класс
случайностей: ассистент *читает* секрет. Другой класс так не закрыть — команда
сама *печатает* секрет. Разбирать в командной строке нечего:

```bash
croc send report.pdf
```

Пароль появляется только в ответе, потому что `croc` повторяет параметры,
которые понадобятся принимающей стороне. Так же ведут себя `docker login`,
подробный режим `curl` и вообще любая программа, которая пересказывает
полученные аргументы.

`secrets-redact` работает хуком `PostToolUse` и заменяет результат через поле
`hookSpecificOutput.updatedToolOutput` — до модели доходит уже изменённый текст.
Что скрывать, решают два уровня.

**Уровень 1 — форматы поставщиков.** `ghp_`, `glpat-`, `AKIA`, JWT, заголовок
приватного ключа, учётные данные внутри URL. Здесь двусмысленности нет, поэтому
такие строки скрываются везде, где встретятся. Список шаблонов посимвольно
совпадает со списком в `safe-env`; `tests/test_redact.sh` сравнивает оба файла и
падает, если они разошлись.

**Уровень 2 — значения с подписью.** Строку из случайных символов скрывают
только тогда, когда что-то в той же строке называет её секретом: `--pass`,
`--token`, `password=`, `api_key=`, `Authorization: Bearer`. Подпись здесь
выполняет настоящую работу. В пароле, ради которого писался этот хук, было 32
шестнадцатеричных символа — ровно столько же в любой сумме md5:

```
croc --relay host:9009 --pass deadbeefdeadbeefdeadbeefdeadbeef code-word
md5sum: deadbeefdeadbeefdeadbeefdeadbeef  report.pdf
```

Строки одинаковые, решения противоположные. Если скрывать любую
шестнадцатеричную строку, под замену попадут все контрольные суммы и хеши
коммитов, с которыми модель работает. А замена, портящая обычный вывод, ведёт
ровно к тому же исходу, что и запрет обычных команд: её выключают.

В метке остаётся длина — `<REDACTED:32>`, — потому что модели обычно нужно
знать, что значение убрали и сколько в нём было символов, а не какое оно было.

### Чем за это приходится платить

Хук срабатывает, когда инструмент уже отработал. Команда выполнилась, все её
последствия остались, а телеметрия ассистента отправляет исходный вывод.
Предотвращается меньшее, но всё ещё важное: секрет не попадает в контекст
модели, а значит, и в журнал сессии, который она пишет, в её пересказ и в
хранилище памяти, которое всё это индексирует.

Отказывает хук тоже в сторону разрешения, по той же причине, что и
`secrets-guard`: нет `jq`, разобрать ввод не удалось или в результате нет
`stdout` и `stderr` — выход 0 без вывода, результат остаётся нетронутым.

## Зачем в комплекте файл правила

Одного запрета мало, и вот почему.

Ассистенту нужно узнать, задан ли ключ. Он получает отказ — и, поскольку задача
никуда не делась, пробует иначе:

```bash
env | grep API          # отказ
printenv | grep API     # отказ
sh -c 'env'             # отказ
```

Каждая попытка — это лишний круг: время пользователя и ещё одна возможность
случайно найти написание, которое проверка не разбирает.

Файл `rules/secrets-hygiene.md` установщик кладёт туда, откуда ассистент читает
свои постоянные инструкции: у Claude Code это `~/.claude/rules/`, у Codex —
`~/.codex/memories/`, у Opencode — `~/.config/opencode/instructions/` (и там же
он вписывает файл в список `instructions`, иначе Opencode его не прочитает).
В файле сказано, чем пользоваться вместо запрещённого:

```bash
safe-env                      # всё окружение, значения секретов скрыты
echo "$ANTHROPIC_MODEL"       # одна переменная, когда известно имя
```

Тогда после первого же отказа ассистент берёт `safe-env`, получает нужный
ответ и идёт дальше.

Итог: `secrets-guard` не даёт напечатать ключ, а правило говорит, как решить
исходную задачу другим способом. Без правила защита всё равно работает — просто
каждый раз обходится в несколько лишних попыток.

## Ключи приходят из родительской оболочки

Знать об этом стоит: это объясняет случай, который иначе выглядит загадочно —
ключ есть в окружении ассистента, но его нет ни в одном файле настроек
оболочки.

Ассистент делает снимок окружения один раз, при запуске. Переменная,
экспортированная в оболочке, из которой его запустили, остаётся во всех его
командах до конца сессии — даже после того, как строку с экспортом убрали из
`.bashrc`. Это проверено чтением `/proc/<pid>/environ` родительского процесса.

Чтобы убрать её по-настоящему: выйти из ассистента, открыть чистую сессию
оболочки, убедиться, что переменной нет (`safe-env | grep NAME`), и запустить
ассистента заново.

## Чего эта защита не делает

- `secrets-guard` не читает **вывод** команд. Его читает `secrets-redact`, но
  только после того, как команда отработала, и только для значений, у которых
  есть подпись. Секрет без подписи, похожий на обычный текст — например,
  парольная фраза из трёх слов, — проходит мимо обоих.
- Это не изолированная среда. Тот, кто намеренно хочет прочитать значение,
  может его закодировать, перевернуть или сначала записать в файл. Цель здесь —
  обычная случайность, а случается на практике именно она.
- Она ничего не меняет в самих ключах. Если ключ попал в журнал сессии, помогает
  только выпуск нового.
