# env2hell

Ассистент выполняет обычную команду вроде `env` — и все ваши ключи и токены
печатаются прямо в сессию, открытым текстом. Прочитать их может любой, у кого
есть доступ к этой переписке. И она не исчезает: сессия сохраняется файлом на
диске, попадает в индексы памяти и в ночные сводки. Так ключи и утекают.

env2hell такие команды запрещает и даёт ассистенту безопасную замену. Работает
с Claude Code, Opencode и Codex — на Linux, macOS и Windows.

[English version](README.md)

## Зачем это нужно

Приложение падает с ошибкой авторизации. Разработчик пишет ассистенту:
«разберись, почему 401». Тот начинает с самого разумного — проверяет, задан ли
вообще ключ:

```bash
env | grep -i api
```

Проверка была правильная. Но `grep` отбирает **строки**, а строка здесь — это
`NAME=value`, поэтому вместе с ответом «да, задан» в сессию печатается и само
значение. Тем же кончаются `cat .env` при разборе настроек и `env` целиком,
когда сравнивают локальный запуск с CI.

Дальше эта строка живёт своей жизнью: сессия сохраняется файлом на диске
(Claude Code пишет `.jsonl`), инструменты памяти её индексируют, ночью
собираются сводки. После одной такой команды менять придётся все ключи на
машине.

Так и появился этот репозиторий: пять токенов (Z.ai, DeepSeek, OpenRouter,
Tavily и собственный токен доступа ассистента) напечатались полностью — в
сессии, где всего-то требовалось назвать версию модели.

Просьба «так не делай» здесь не работает. Инструкция — это рекомендация, а
нужен запрет.

## Из чего состоит

| Команда | Назначение |
|---|---|
| `secrets-guard` | Запрещает команду до запуска. Ассистенты вызывают его сами. |
| `safe-env` | Печатает окружение, скрывая значения секретов. Замена, которой пользуется модель. |

Вместе с ними в каждый ассистент ставится файл правила
(`rules/secrets-hygiene.md`) — чтобы модель знала про замену, а не боролась с
запретом.

### Что запрещено

```
env                     printenv                export -p
set                     declare                 history
env | grep KEY          rtk env                 ls && env
cat .env                head ~/.bashrc          cat /proc/1/environ
cat ~/.ssh/id_rsa       head ~/.aws/credentials
```

### Что по-прежнему работает

```
safe-env                        # все переменные, значения секретов скрыты
safe-env | grep MODEL           # фильтровать можно — значения уже скрыты
echo "$ANTHROPIC_MODEL"         # одна переменная по имени
printenv PATH                   # одна переменная, явно
env VAR=value some-command      # задаёт переменную команде, ничего не печатает
awk '/env|set/ {print}' f.txt   # слово внутри программы в кавычках — не команда
```

Последняя строка важнее, чем кажется. Запрет, который не отличает команду `env`
от слова `env` внутри регулярного выражения, в первый же час мешает обычной
работе — и его выключают.

## Установка

### Linux и macOS

```bash
git clone <этот-репозиторий> env2hell && cd env2hell
./install.sh                 # во все найденные ассистенты
./install.sh --dry-run       # показать, что будет сделано, ничего не менять
./install.sh --ide claude    # только в один ассистент
```

Нужен Python 3.8 или новее: файлы настроек ассистентов — это JSON.

### Windows

Ни Python, ни Git Bash не требуются: у запрета есть версия на PowerShell, и
установщик тоже написан на PowerShell.

```powershell
.\install.ps1
.\install.ps1 -DryRun
.\install.ps1 -Ide claude
```

Если файл не запускается, его не пускает политика выполнения PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

**После установки перезапустите ассистента.** Хуки и плагины читаются один раз,
при запуске; до перезапуска ничего не проверяется.

## Как этим пользоваться

Руками запускать нечего. Ассистент вызывает запрет перед каждой командой, а при
отказе получает сообщение о том, чем пользоваться вместо неё:

```
[secrets-guard] Blocked: bare env/printenv/export/set/declare leaks secrets to
the session. Use `safe-env` (values masked), or `echo "$VAR"` for one value.
```

`safe-env` пригоден и для ручной работы — когда окружение нужно посмотреть, но
не хочется оставлять его в журнале:

```
$ safe-env | grep -E 'TOKEN|MODEL'
ANTHROPIC_MODEL=glm-5.2
GITHUB_PERSONAL_ACCESS_TOKEN=<REDACTED:93>
TAVILY_API_KEY=<REDACTED:57>
```

Длина значения сохраняется: она позволяет различить два разных ключа и при этом
не даёт ничего, чем можно воспользоваться.

## Проверка

```bash
./tests/test_guard.sh          # 36 случаев против версии для POSIX
./tests/test_guard.sh --pwsh   # те же 36 против версии для PowerShell
```

Обе версии дают `passed 36, failed 0`.

## Удаление

```bash
./uninstall.sh                 # отключить во всех ассистентах, убрать обе команды
./uninstall.sh --dry-run
./uninstall.sh --keep-bin      # только отключить, команды оставить
```

Копии файлов настроек, сделанные при установке, не удаляются: в них лежит то,
как настройки выглядели раньше, и удалять их означало бы обессмыслить саму
привычку их делать.

## Куда именно встраивается

| Ассистент | Механизм |
|---|---|
| Claude Code | Хук `PreToolUse`, шаблон `Bash`, в `settings.json` |
| Codex | Хук `PreToolUse`, шаблон `^Bash$`, в `hooks.json` |
| Opencode | Запрещающие правила `permission.bash` **и** плагин `tool.execute.before` |

Opencode требует обоих слоёв. `permission.bash` сравнивает начало строки
команды, поэтому сам по себе он никогда не увидит `env | grep X`, `rtk env` или
`a && env`. Настоящую проверку выполняет плагин, вызывая тот же
`secrets-guard`, — так правило остаётся в одном месте вместо двух, которые со
временем разойдутся.

## Границы применимости

- Запрет видит команду **до** запуска. Вывод он не читает, поэтому программа,
  которая сама печатает ключ, под него не попадает.
- Это фильтр, а не изолированная среда. Он повышает цену обычной случайности,
  но не защищает от того, кто намеренно достаёт значение.
- Ключ, уже попавший в окружение, там и останется. Ассистент делает снимок
  окружения при запуске, поэтому удаление переменной из `.bashrc` не убирает её
  из работающей сессии — подробнее в разделе
  [как это устроено](docs/design.ru.md).
